# 통계표 찾기와 계산의 기준 합치기 (설계, 2026-11-23)

작성: jenna.jyyun (Claude Code와 함께) · 상태: 설계 (코드는 아직 안 바꿈)

## 요약

- **문제**: 통계표 찾기가 "조건을 모두 만족하는 표"라고 했는데, 계산이 칸을 못 골라 표 안내로 끝나는 질문이 있다. V2 1차에서 19문항.
- **원인**: 두 단계가 서로 다른 기준으로 판정한다.
  - 통계표 찾기: "이 **표**가 조건을 담나?"
  - 계산: "조건마다 **칸**을 하나씩 정할 수 있나?"
- **해결**: 질문의 조건을 표의 칸에 잇는 일을 **한 번만** 한다. 모든 조건이 칸에 이어진 표만 "조건 충족"이다. 계산은 이어진 칸으로 값을 꺼내기만 한다.

## 1. 예시 하나로 보기

**V2-034** "2010년에 애를 셋 이상 낳은 기혼 여성 다 합치면 몇 명이었어?"

통계표 찾기가 1위로 고른 표: `DT_1PF1004` 사망자녀 수 및 출생자녀수별 기혼여성인구(15세 이상)

| 분류 | 칸 |
|---|---|
| 항목 | 기혼여성(15세 이상)-계, 출생자녀 0명, 1명, 2명, **3명, 4명, … 10명이상** |
| 행정구역 | 전국, 서울특별시, … |
| 사망자녀수 | 계, 0명, 1명, 2명, 3명 이상 |

맞는 표다. 출생자녀 3명 ~ 10명이상 칸을 더하면 답이 나온다.

**지금 일어나는 일**

| 단계 | 판정 | 결과 |
|---|---|---|
| 통계표 찾기 | 표 이름에 '기혼여성' → 성별 '여' 만족 · 2010년 있음 | ✅ 조건 모두 충족 |
| 계산 | 성별 '여'를 물었는데 성별 분류가 없음 | ❌ "표에 성별 구분이 없음" |
| 최종 답 | | 표 안내만 |

통계표 찾기는 "표 전체가 여성이니 성별 조건은 이미 만족"으로 봤다. 계산은 그 판단을 모르고 "성별 분류가 있어야 한다"는 자기 규칙으로 다시 판정했다.

**바꾼 뒤**

| 조건 | 이어진 곳 | 어떻게 |
|---|---|---|
| 성별 '여' | (칸 필요 없음) | 표 전체가 기혼여성 |
| '셋 이상' | 항목: 출생자녀 3명 ~ 10명이상 | 칸 이름의 숫자 |
| 2010년 | 수록 기간 안 | |
| 말하지 않은 분류 | 행정구역: 전국, 사망자녀수: 계 | 합계 칸 |

모든 조건이 이어졌으니 조건 충족이고, 계산은 이 칸들을 더하기만 한다.

## 2. 왜 이런 일이 생기나

### 원인 ① 판정하는 대상이 다르다

| | 통계표 찾기 | 계산 |
|---|---|---|
| 보는 것 | 표 정보 (표 이름, 분류 이름, 항목 목록, 연령 범위, 기간) | 표의 실제 칸 |
| 묻는 것 | 이 표가 조건을 **담나** | 조건마다 칸을 **정할 수 있나** |
| 넘기는 것 | 조건마다 참/거짓 | — |

통계표 찾기는 참/거짓만 넘기고, **왜 참인지는 넘기지 않는다.** 그래서 계산은 처음부터 다시 판정한다. 계산 쪽 규칙이 더 좁아서, 통계표 찾기가 통과시킨 표를 계산이 떨어뜨린다.

조건별로 보면:

| 조건 | 통계표 찾기는 이런 경우도 통과 | 계산은 이것만 받음 | 어긋난 문항 |
|---|---|---|---|
| 성별 | 여성만 다루는 표, 항목에 남자/여자 | 성별 분류 | V2-034, 103, 142 |
| 연령 | 표 이름의 연령 범위 ('65세이상') | 연령 분류 | V2-013, 090 |
| 항목 | 낱말 줄기, 동의어 사전 | 칸 이름 글자, 동의어 2개, LLM | V2-012, 031, 057 … |
| 지역 | 그 지역만 다루는 표 | 지역 분류의 이름 | V2-027 |

### 원인 ② 같은 질문을 네 번 해석한다

```
질문
 ├─ ① 질문 이해 (HCX)                → 지표 · 지역 · 연도 · 성별 · 연령
 ├─ ② 통계표 찾기 (Gemma)            → 주제 · 조건 → 표마다 참/거짓
 ├─ ③ 계산: 칸 고르기                 → 질문 글자 맞추기 · LLM 칸 고르기
 └─ ④ 계산: 조건 반영 검사            → 고른 칸에 조건이 들어갔나 다시 확인
```

해석하는 곳이 많을수록 어긋날 곳도 많다. 예: **V2-012**에서 ③의 LLM은 "미성년 자녀 셋 = '3자녀' 칸"이라고 맞게 골랐는데, ④에서 "질문의 말과 맞는 칸이 없음"으로 떨어졌다.

## 3. 어떻게 바꾸나

### 지금

```
통계표 찾기 ──(참/거짓)──▶ 계산: 칸 고르기 ──▶ 계산: 조건 검사 ──▶ 값
                            (다시 해석)          (또 다시 해석)
```

### 바꾼 뒤

```
통계표 찾기 ──▶ ★ 조건 → 칸 잇기 (표마다 한 번) ──▶ 계산: 값 꺼내기 · 더하기 · 비교
                  │
                  └ 모든 조건이 이어진 표 = 조건 충족
```

바뀌는 것 세 가지:

1. **"조건 충족"의 뜻**: "표가 조건을 담는다"에서 "모든 조건이 칸에 이어졌다"로 바뀐다. 조건 충족인데 계산 실패는 정의상 생기지 않는다.
2. **계산이 하는 일**: 질문을 다시 해석하지 않는다. 이어진 칸으로 값만 꺼낸다.
3. **실패 이유**: "어떤 조건을 어느 칸에도 잇지 못했다"가 표마다 남는다. 이걸 그대로 사용자 안내와 평가 분석에 쓴다. "혼인 건수 자료는 1990~2025년만 있습니다"처럼 엉뚱한 안내로 덮이지 않는다.

잇는 일은 통계표 찾기가 뽑은 **상위 후보 몇 개**(5개 안팎)에만 한다.

## 4. 잇기 결과의 모양

V2-034의 1위 표라면:

```json
{
  "tbl_id": "DT_1PF1004",
  "status": "bound",
  "bindings": [
    {"cond": "sex",  "value": "여",      "by": "table",  "note": "표 전체가 기혼여성"},
    {"cond": "item", "value": "셋 이상", "by": "value",  "dim": "항목", "cells": ["출생자녀 3명", "…", "출생자녀 10명이상"]},
    {"cond": "year", "value": 2010,      "by": "period"}
  ],
  "defaults": [
    {"dim": "행정구역", "cell": "전국"},
    {"dim": "사망자녀수", "cell": "계"}
  ],
  "unbound": []
}
```

- `status`: 모두 이어지면 `bound`, 일부만이면 `partial`, 주제부터 안 맞으면 `none`
- `unbound`: 잇지 못한 조건과 이유 (예: `"부부 사이가 안 좋아서" → 맞는 칸 없음, 후보: 부부불화 · 경제문제`)
- `defaults`: 질문이 말하지 않아 합계 · 기본값으로 둔 분류 (답에 알린다)

`by`는 어떻게 이었는지다:

| `by` | 뜻 | 예 |
|---|---|---|
| `value` | 칸 이름이 그대로 맞음 | '3자녀' |
| `dictionary` | 동의어 사전 | '결혼' → 혼인 |
| `llm` | LLM이 고름 | '부부 사이가 안 좋아서' → 부부불화 |
| `table` | 표 전체가 이미 그 조건 | 기혼여성 표의 성별 '여' |
| `age_range` | 연령 구간 칸들 | 30대 → 30~34세, 35~39세 |
| `couple` | 부부 단위 표의 남편 칸 | 혼인 건수 (#208) |
| `split` | 한 칸으로 못 정해 남녀를 따로 보임 | 30대 혼인: 남편 · 아내 (#208) |

## 5. 조건별 잇기 규칙

새로 만드는 규칙은 거의 없다. 지금 통계표 찾기(`search.check`)와 계산(`dynamic_indicator.choose`, `uncovered`)에 흩어져 있는 규칙을 한곳으로 모은다.

| 조건 | 위에서부터 차례로 시도 |
|---|---|
| 성별 남/여 | 성별 분류의 칸 → 항목의 남자/여자 칸 → 표 전체가 그 성별 |
| 성별을 말하지 않음 | 합계 칸 → '인구' · '총인구' 같은 대상 전체 칸 → 부부 단위 표면 남편 칸 → 남녀 따로 |
| 연령 | 연령 구간 칸들 → 표 이름의 연령 범위가 질문과 같으면 표 전체 |
| 항목 · 분류 값 | 칸 이름 그대로 → 낱말 줄기 → 동의어 사전 → LLM |
| 나눠 보기 ('~별') | 그 분류 전체 |
| 지역 | 지역 칸 → 그 지역만 다루는 표 → 지역 묶음(수도권 · 호남)은 시도 칸들의 합 |
| 연도 | 수록 기간 안 (공표 시차 허용) |
| 제외 ('~빼고') | 합계에 그 대상이 들어 있으면 잇지 못함 |

**LLM은 규칙으로 잇지 못한 조건에만** 쓴다. 지금은 검토 LLM(표 고르기)과 칸 고르기 LLM(계산)이 같은 표를 따로 보는데, 이를 하나로 합친다. LLM이 고른 칸은 뒤에서 다시 떨어뜨리지 않는다.

필요한 정보는 이미 있다. `catalog.table_meta`에 표 2364개 모두의 항목 목록이 있어서, 값이 적재되지 않은 표도 칸 이름으로 이을 수 있다.

## 6. 진행 순서

한 번에 바꾸면 지금 맞히는 문항이 깨질 수 있다. 단계마다 V1 · V2 개발셋을 돌려 확인하고 넘어간다.

| 단계 | 하는 일 | 답이 바뀌나 | 다음으로 넘어가는 기준 |
|---|---|---|---|
| 0 | 평가에 "표 찾기 ok인데 계산 실패" 건수와 이유를 따로 집계 | 아니오 | 지금 값 기록 (V2 1차: 19) |
| 1 | 잇기 단계를 만들고 결과를 **기록만** | 아니오 | 지금 계산이 성공한 문항에서, 잇기가 고른 칸 = 지금 고른 칸 |
| 2 | 잇기 결과를 계산에 사용 (기존 판정과 다르면 기록) | 예 | 정답 수가 줄지 않음 · A · B · D 유형이 계산됨 |
| 3 | 표 순위와 "조건 충족"을 잇기 결과로 | 예 | '일부 일치' 안내가 잇지 못한 이유로 나옴 |
| 4 | 계산 쪽의 다시 해석하는 코드 걷어 내기 | 아니오 | 테스트 · 평가 그대로, LLM 호출 수 같거나 줄어듦 |

1 · 2단계는 설정(`.env`)으로 켜고 끈다. 기본은 끄고, 평가를 보고 켠다.

계산 쪽에 이어진 칸을 넘기는 길은 이미 있다. 되묻기에서 사용자가 고른 칸을 넘기는 `forced`와 같은 방식으로 넘기면 된다.

### 6-3. 2단계에서 지킬 것 (1단계에서 배운 것)

- **잇기는 후보 표마다 따로 돈다. 엉뚱한 후보 표도 '모두 이음'이 된다.** V2-031의 가구원수 표('3인 ~ 7인 이상'), V2-034의 '추가 계획 자녀 3명이상' 표, V2-077의 이혼 표. → 2단계 첫 판은 **검토가 고른 표(kind picked)에만** 잇기를 쓴다. 표 순위는 통계표 찾기 그대로
- **지금 계산이 성공한 표는 건드리지 않는다.** 잇기는 지금 계산이 칸을 못 고른 표에서만 다시 계산한다 (규칙 → 잇기 → 칸 고르기 LLM 순서. 잇기로 되면 LLM 호출이 준다)
- **칸이 여럿인 조건은 한 분류 안의 연산(plan.multi → parts_answer)으로 넘긴다**: 수 범위는 합, 나눠 보기는 순위(순위를 물었거나 '상위 N') 또는 비교. 순위에서 '기타 · 미상' 칸은 뺀다 (V2-077 골든 기준)
- **잇기로 계산한 결과는 계산 방법 캐시(plan_cache)에 남기지 않는다** (캐시는 칸 하나씩만 담아 다음 질문에 다르게 쓰일 수 있다)
- **수 조건이 무엇을 센 것인지**: '셋 이상'이 자녀 수인지 가구원 수인지는 칸의 수만으로 모른다. 검토가 고른 표에만 쓰는 것으로 1차로 막고, 2단계 평가에서 다시 본다
- 남은 것: '둘 다 실패'(V2.3 14건)의 대부분은 질문 말 ↔ 칸 이름이 달라 규칙으로 못 잇는다 ('부부 사이가 안 좋아서' ↔ 부부불화, '결혼 나이' ↔ 평균초혼연령). 잇기에 LLM을 붙이는 것은 2단계 다음 판

## 7. 정해야 할 것

1. **값이 많은 분류**: 시군구(329개) 같은 큰 분류는 표 정보에 일부 값만 있다. 지역은 지금처럼 따로 잇고, 나머지는 적재 후 다시 잇는 것으로 충분한가? → 1단계 기록으로 확인
2. **검토 LLM**: 잇기 LLM이 생기면 검토 LLM과 하는 일이 겹친다. 합칠까, 검토는 표 고르기만 하게 둘까? → 1단계 기록을 보고 결정
3. **해석 합치기**: 질문 이해(HCX)와 통계표 찾기(Gemma)는 같은 질문을 다른 틀로 읽는다. 잇기 단계가 어느 쪽을 기준으로 삼을까? → 이번 범위 밖. 둘을 Gemma 한 번으로 합치는 실험은 이미 있다 (`67ede58`, `UNDERSTAND_MERGED=gemma`, 기본 끔). 정답은 1문항 늘었지만 기대 행동 일치가 8문항 줄어 기본으로 쓰지 않았다. 잇기 단계가 자리 잡은 뒤 이 스위치를 켜고 다시 재 본다
4. **속도**: 후보 5개 안팎 × 조건 수만큼 규칙을 돌린다. 규칙은 빠르지만 LLM은 질문당 지금 상한(3회) 안에서만 부른다.

**이번 범위가 아닌 것**: 큰 표 적재 (V2-015 · 016 · 033), 지표 사전으로 답하는 질문, 표 검색 순위 자체

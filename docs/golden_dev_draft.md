# 개발셋 초안 문항 정리

- 원본: [eval/dev_draft.jsonl](../eval/dev_draft.jsonl) (이 문서는 원본에서 자동 생성)
- 기준 문서: 골든셋 설계 (2026-10-30)
- 문항 수: **41** (범위 안 37 + 범위 밖 4)
- id: d42부터 시작 (초기 41문항 d01~d41과 겹치지 않게)
- 출처: 모두 `역생성` (표를 보고 거꾸로 쓴 질문) → **개발셋 전용**, 테스트셋에 쓰지 않음
- 상태: **미확인**. 모든 문항 `checked_by`가 비어 있음. 두 사람이 확인해야 확정

## 1. 확인할 때 볼 것

문항마다 아래 네 가지를 보고, 맞으면 `checked_by`에 이름을 넣는다. 의견이 갈리면 보류(`hold.jsonl`)로 옮긴다.

1. **정답 표가 맞는가**: 질문만 보고 직접 표를 찾았을 때 같은 표가 나오는가
2. **빠진 정답은 없는가**: 다른 조사·다른 표로도 답할 수 있는데 `정답 표`에 없는 경우
3. **(패밀리·되묻기) 최종 표가 맞는가**: ★ 표시 표가 성별·연령·기간 판까지 맞는가
4. **(되묻기) 정말 되물어야 하는가**: 합계 표가 있어서 되묻지 않아도 되는 건 아닌가

표기: `정답 표`의 ★ = 최종 표(`final_table`). 괄호 안은 표에 담긴 기간.

## 5. 공통으로 알아둘 점

- **`gold_family`·`fam_size`는 추정값이다.** 판묶기 코드가 이 저장소에 없어 표 이름으로 묶음을 추정했다. 판묶기 코드로 돌려 실제 묶음과 맞춰야 한다.
- **성별만 다른 묶음은 되묻기로 쓰지 않았다.** 규칙 5(성별 미지정 → 계)에 따라 되물을 필요가 없다. 되묻기 문항은 모두 합계 표가 없는 묶음에서 골랐다.
- **2015년이 들어간 질문은 피했다.** 외국인주민현황은 2007~2015판과 2015판이 2015년에서 겹치는데, 규칙 4(판 선택)가 이 경우를 정하지 않는다. 설계 문서 규칙 4 보완이 필요하다.
- **범위 밖 질문으로 쓰면 안 되는 주제가 있다.** 인구총조사에 전세금 규모별 가구, 실업자 수(과거 연도) 표가 있다. '전세', '실업' 질문은 범위 밖이 아니다. 설계 문서의 예시 '청년 실업률'도 재검토 필요.
- **조사 비율이 계획과 다르다.** 인구총조사가 적고(설계는 40%) 사할린동포 조사가 많다. 합계 표 없이 나뉜 묶음이 사할린 조사에 몰려 있기 때문이다. 문항을 더 채울 때 맞춘다.
- **메타데이터 이상 1건**: `DT_358005_017`은 표 이름이 '(생산직)'인데 항목 이름이 '(사무관리직)'으로 적재돼 있다.

# 데이터 사전

KOSIS 원본 통계표 20개를 전처리해 만든 DB(`data/processed/kosis.duckdb`)의 구성과 사용법.

- 원본: `data/raw/kosis_zip/processed/*.csv` (+ 표마다 `.meta.json`). `--source collect`로 실행하면 수집기 출력 `data/processed/*.csv` (zip 안의 CSV와 같은 파일)
- 결과: `data/processed/kosis.duckdb` (DuckDB 파일 하나, 테이블 15개)
- 만드는 코드: `pipeline/run_all.py` → `preprocess.py` → `catalog.py` → `validate.py`
- `data/`는 git에 올리지 않는다. 받는 방법은 팀 공유 zip(`dist/`) 또는 원본 zip을 `data/kosis_processed.zip`에 두고 `python pipeline/run_all.py`

원본 CSV는 이미 "한 행 = 값 하나"인 세로형이다. 주요 열은 아래와 같다.

```
tbl_id, period(연도), item_id, item_nm(항목), c1_id/c1_nm, c2_id/c2_nm, c3_id/c3_nm(분류), value, value_flag(결측 기호), unit
```

문제는 **표마다 규칙이 다르다**는 점이다.
- 지역이 대부분 `c1`에 있지만 장래추계 표는 `c2`에 있다 (`c1` = 시나리오, `c3` = 지표 이름).
- 지역 코드 체계가 표마다 다르다 (예전 체계에서 `31` = 경기도, 현재 `31` = 울산광역시).
- 단위가 비어 있거나, 여러 단위가 한 칸에 합쳐져 있다.
- 결측이 `*`, `-`, `x` 같은 기호로 들어 있다.

## 2. 어떻게 합쳤나

```
CSV 20개 ──(preprocess.py)──▶ 데이터 테이블: facts, population
meta.json 20개 ─────────────▶ catalog
주민등록인구 표의 지역 ───────▶ regions, region_aliases, region_changes, region_code_map
config/catalog_notes.toml ──(catalog.py)──▶ 설명 테이블: indicator_dict, table_notes ...
                              ──(validate.py)──▶ 검사 19개, 하나라도 실패하면 중단
```

**3차원이나 피벗 구조가 아니다.** 20개 표를 *같은 열 구조로 맞춘 뒤 위아래로 쌓은* 2차원 세로형 표(`facts`)다. 연도·지역·성별·연령 같은 기준은 모두 **열 하나씩**으로 들어 있다.

정리한 내용 (`pipeline/preprocess.py`)

| 무엇을 | 어떻게 | 코드 |
|---|---|---|
| 지표 이름 위치 통일 | 표마다 `item_nm`, `c1_nm`, `c3_nm`에 흩어진 지표 이름을 `label` 열 하나로 | `LABEL_COLUMN`, `load_raw` |
| 지역 기준 정하기 | 주민등록인구 표(DT_1B04006)의 지역 310개를 기준 목록(`regions`)으로 | `build_regions` |
| 지역 코드 통일 | 표별 지역을 기준 코드로 연결. 코드+이름 → '시도 > 시군구' 경로 → 시도 이름 순으로 확인 | `build_region_map` |
| 연도별 지역 | 행정구역 변경 반영 (예: 군위군 2022년까지 경북 `47720`, 2023년부터 대구 `27720`) | `valid_from`, `valid_to` |
| 단위 정리 | 빈 단위를 표·항목·지표 이름 규칙으로 채움 | `UNIT_OVERRIDES`, `LABEL_UNIT_RULES` |
| 결측 정리 | 기호를 이유 문장으로 (`*` → 비밀보호 (5 미만)) | `MISSING_REASONS` |
| 가짜 0 제거 | 전남광주통합특별시 출범(2026) 전 기간의 0은 결측으로 | `PLACEHOLDER_REGIONS` |
| 추계 구분 | 장래추계 표의 2023년 이후 값에 `is_projection = true`, 시나리오 표시 | `PROJECTION_TABLES` |
| 코드 앞자리 0 보존 | CSV를 모두 문자열로 읽음 (`00`, `011`이 `0`, `11`이 되지 않게) | `load_raw` |

그다음 가장 많이 쓰는 주민등록인구 표만 따로 `population`으로 다듬었다 (성별·연령을 열로, 연령을 숫자로). `build_population` 참고.

## 4. 열 설명

### 4-1. `population`

| 열 | 타입 | 의미 | 값 |
|---|---|---|---|
| `year` | 정수 | 연도 (12월 31일 기준) | 2008 ~ 2025 |
| `region_code` | 문자 | 지역 코드. 이름은 `regions`에서 | 309개. `00` 전국, `26` 부산광역시, `26110` 부산 중구 |
| `sex` | 문자 | 성별 | `계`(남녀 합계), `남`, `여` |
| `age` | 정수 | 나이 (1세 단위) | 0 ~ 100. **NULL = 전체 연령 합계** |
| `is_open_age` | 참/거짓 | "○세 이상" 묶음 구간인지 | `100세 이상`만 true |
| `age_label` | 문자 | 원본의 나이 이름 | `계`, `0세` ~ `99세`, `100세 이상` |
| `population` | 정수 | 인구 수 (명) | |

- 한 지역·한 해에 306행 = 성별 3개 × 연령 102개 (계 + 0~99세 + 100세 이상)
- 성별은 원본 항목에서 나왔다: `T2 총인구수` → 계, `T3 남자인구수` → 남, `T4 여자인구수` → 여
- `계`는 원본 값이다 (계산한 값이 아님). `남 + 여 = 계`인지 validate.py가 검사한다.

### 4-2. `regions`

| 열 | 타입 | 의미 | 값 |
|---|---|---|---|
| `region_code` | 문자 | 지역 코드 | `00`, `26`, `26110` |
| `region_name` | 문자 | 지역 이름 | `부산광역시`, `중구` |
| `kind` | 문자 | 지역 종류 | `전국`(1), `시도`(18), `시군구`(238), `일반구`(38), `출장소`(15) |
| `sido_code`, `sido_name` | 문자 | 소속 시도 | 전국·시도는 NULL |
| `path` | 문자 | 전체 경로 | `부산광역시 > 중구` |
| `is_basic` | 참/거짓 | 기초자치단체(시군구)인지 | 합계를 낼 때 이 행만 더한다 |
| `first_year`, `last_year` | 정수 | 데이터에 처음/마지막으로 나온 해 | |
| `valid_from`, `valid_to` | 정수 | 지역이 존재한 기간. NULL = 제한 없음 | 경북 군위군 `~2022`, 대구 군위군 `2023~` |

- `일반구`(예: 수원시 장안구)와 `출장소`는 시군구 안에 포함된다. 같이 더하면 중복 집계된다.
- 알려진 문제: 일반구의 `path`에 상위 시가 빠져 있다 (`경기도 > 장안구`). 그래서 "장안구", "경기 장안구"는 찾지만 "수원시 장안구"는 `unknown_region`이 된다. 질문 이해 단계라 회차 4 이후에 고친다.
- 310개 중 `12` 전남광주통합특별시(2026 출범)는 아직 인구 자료가 없다.

### 4-3. `facts`

| 열 | 타입 | 의미 | 값 |
|---|---|---|---|
| `tbl_id` | 문자 | 원본 표 ID | 20개 (`catalog` 참고) |
| `year` | 정수 | 연도 | 표마다 다름 (1970 ~ 2052) |
| `item_id`, `item_nm` | 문자 | 원본 항목 코드·이름 | `T1`, `평균초혼연령` |
| `label` | 문자 | **지표 이름** (위치 통일) | `남편`, `아내`, `합계출산율` |
| `region_code` | 문자 | **기준 지역 코드** | `regions`와 같은 코드. 연결 못 하면 NULL |
| `region_match` | 문자 | 지역 연결 방법 | `code`, `path`, `sido`, `total`, NULL |
| `c1_id` ~ `c3_nm` | 문자 | 원본 분류값 그대로 | 표마다 뜻이 다름 (`.meta.json`의 `classes`) |
| `value` | 실수 | 값 | |
| `unit` | 문자 | **정리된 단위** | `명`, `세`, `%`, `가임여성 1명당 명` |
| `is_missing` | 참/거짓 | 결측인지 | 약 9.7만 행 |
| `missing_symbol` | 문자 | 원본 결측 기호 | `*`, `-`, `x` |
| `missing_reason` | 문자 | 결측 이유 | `비밀보호 (5 미만)` 71,309 / `해당 자료 없음` 14,472 / `비밀보호` 10,497 / 통합특별시 출범 전 자리값 1,144 |
| `scenario` | 문자 | 장래추계 시나리오 | 실적 표는 NULL |
| `is_projection` | 참/거짓 | 추계값인지 | 장래추계 표의 2023년 이후만 true |
| `last_changed` | 날짜 | KOSIS 원본 최종 수정일 | |

- 값 하나를 정하려면 `tbl_id` + `year` + `region_code` + `label`(+ 필요하면 `c2`, `c3`, `scenario`)까지 지정해야 한다.
- `region_code`가 NULL인 행(약 7.4만)은 "변동전 지역", "동부/읍부/면부", "국외"처럼 지역 목록에 연결할 수 없는 분류다.

## 5. 비율·지표는 어디서 나오나

**비율을 미리 계산해서 저장한 표는 없다.** 지표는 두 종류다 (`indicator_dict.method`).

### 5-1. 계산 지표 (`computed`, 4개): 질문할 때마다 `population`에서 계산

`app/services/indicators.py`의 `INDICATORS`와 `_components`.

| 지표 | 계산식 | 단위 | 차이 단위 |
|---|---|---|---|
| 총인구 | `age is null`인 행 | 명 | 명, 증감률 % |
| 고령인구 비율 | 65세 이상 ÷ 총인구 × 100 | % | %p |
| 유소년인구 비율 | 0~14세 ÷ 총인구 × 100 | % | %p |
| 노령화지수 | 65세 이상 ÷ 0~14세 × 100 | 유소년인구 100명당 명 | 포인트 |

- 65세 이상에는 `100세 이상` 묶음이 포함된다 (`age >= 65`).
- 결과는 소수 둘째 자리에서 반올림한다.
- 수록 기간(2008~2025) 밖 연도는 장래추계 표 `DT_1BPB002`(중위 추계)의 같은 지표로 안내한다. status는 `out_of_range`(실적 없음) 그대로 두고, 추계값은 `suggestion`에 담아 답변에 대신 보여준다.
- "6~11세 인구", "65세 이상 인구"처럼 연령 구간 인구 수도 같은 표에서 계산한다 (`indicators._get_indicator`의 ages).

### 5-2. 조회 지표 (`lookup`, 32개): KOSIS가 공표한 값을 `facts`에서 꺼냄 (`app/services/lookup.py`)

전체 목록과 표·항목·필터는 `config/catalog_notes.toml`의 지표 사전이 원본이다. 주요 지표:

| 지표 | 표 (항목) | 지역 수준 | 기간 |
|---|---|---|---|
| 출생아 수 | DT_1B8000H (T10) / DT_1B81A23 (T1) / INH_1B8000F_01 (전국) | 시도 / 시군구 / 전국 | 1990~ / 2000~ / 1970~2025 |
| 합계출산율 | DT_1B81A21 (T1) / DT_1B81A23 (T2) / INH_1B8000F_01 (전국) | 시도 / 시군구 / 전국 | 1993~ / 2000~ / 1970~2025 |
| 조출생률, 사망자 수, 조사망률, 자연증가 건수 | DT_1B8000H | 시도 | 1990~2025 |

## 6. 주의사항 (틀리기 쉬운 것)

**집계**
- 성별은 하나만 고른다. `계`, `남`, `여`를 다 더하면 두 배가 된다.
- 총인구는 `age is null` 행이다. 0~100세 행을 더해도 같은 값이 나온다.
- `100세 이상`은 100세 한 살이 아니라 묶음이다 (`is_open_age`).
- 시도 합계 = `is_basic = true`(시군구)의 합. 일반구·출장소를 같이 더하면 중복이다.
- 이름이 같은 지역이 많다 (`중구`, `동구`, `서구` ...). 이름이 아니라 코드나 `path`로 구분한다.

**비교**
- 그룹이 다른 표는 기준 시점과 대상이 달라서 직접 이어 비교하지 않는다. `table_groups`, `compatible_groups` 참고.
  - 주민등록인구: 12월 31일, 내국인 / 장래추계: 7월 1일, 외국인 포함 / 외국인주민: 11월 1일
- 인구동향(출생·사망 등)은 1년간 **건수(flow)**, 주민등록인구는 특정 시점의 **인구(stock)**다.

**시계열 단절 (`series_breaks`)**
- 2010년: 주민등록인구에 거주불명자 포함 시작
- 2015년: 재외국민 포함 시작
- 이 해의 증가분에는 기준 변경 효과가 섞여 있다.

**행정구역 변경 (`region_changes`)**
- 2023년 군위군이 경북에서 대구로 편입. 대구 인구 추이를 볼 때 2023년에 늘어난 몫이 있다.
- 장래추계의 대구에는 군위군이 포함되지 않는다 (`region_notes`).
- 2026년 광주광역시 + 전라남도 → 전남광주통합특별시, 인천 구 개편. 연간 자료는 2025년까지라 아직 반영된 자료가 없다.

**알려진 데이터 문제**
- `facts.scenario` 표기가 표마다 다르다: `DT_1BPB002`, `DT_1BPB003`은 `중위 추계`, `고위 추계`, `저위 추계`, `무이동 추계`이고, `DT_1BPB101`은 `중위`, `고위`, `저위`다. 시나리오로 조회할 때 주의.
- `DT_1MR2060`(인구총조사)의 기준 시점은 원표에서 확인하지 못했다.

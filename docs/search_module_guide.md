# 질의 이해 · 통계표 탐색 모듈: 흐름, LLM의 역할, 되묻기

작성: 최세진 · 2026-11-17

## 한눈에

- 통계표 찾기는 새 질문 하나에 LLM을 3번 부릅니다(조건 추출, 계획, 검토).
- 조건이 맞으면 한 번 더 부릅니다.
    - 검토가 표를 하나 고른 뒤에, 그 표와 **이름이 거의 같은 표가 후보에 또 있으면** LLM에게 한 번 더 묻습니다.
        - "이 표를 골랐다. 그런데 이름이 거의 같은 표가 더 있다. 질문에 답하려면 이 표들도 함께 봐야 하는가?"
        - EX : "외국인 배우자 국적별 이혼 통계"
            1. 검토가 "외국인 **아내**의 국적별 이혼" 표를 고릅니다.
            2. 후보에 "외국인 **남편**의 국적별 이혼" 표가 있습니다. 이름이 한 낱말만 다릅니다.
            3. 여기서 4번째 호출이 나갑니다. LLM이 "배우자는 아내와 남편을 다 뜻하니 남편 표도 함께 봐야 한다"고 답합니다.
            4. 답변에 "이 통계는 표가 나뉘어 있어 아래 표도 함께 보셔야 합니다"가 붙습니다.
- LLM은 세 가지를 합니다: 질문을 조건으로 옮기기(조건 추출 · 계획), **검색 상위 후보 중에서 최종 표를 고르기**(검토), 범위 밖 질문 거절하기(검토).
- 코드가 먼저 조건을 만족하는지(✔ / ✘) 확인하고, 되물어야 하는지를 정합니다.
- 그다음 검토(LLM)가 상위 후보 8개를 다시 봅니다. 코드와 판단이 다르면 검토를 따릅니다.
    - 코드의 1위가 아닌 표를 LLM 검토가 골랐으면 그 표로 답합니다.
    - LLM 검토가 "조건을 모두 충족한다"고 한 표에는, 코드가 낱말이 달라서 매긴 ✘를 붙이지 않습니다(표는 "주점업", 질문은 "술집").
- 말의 모호함은 유형마다 따로 풉니다. "서울에서 이사 간 사람"(밖으로만인지, 안에서 옮긴 것도 포함인지)은 묻고, 연도 없음은 마지막 해로 정하고, **"외국인"은 답하면서 기준을 밝히고**, "배우자"는 표를 함께 냅니다.
    - **뜻이 갈리는 말 전반을 알아채서 묻는 장치는 아직 없습니다** ⇒ **조금 더 구체적으로 생각해 봐야 함**
- 되묻기는 다섯 가지이고 모두 규칙으로 판정합니다. Gemma로 바꾼 뒤 "비슷한 표가 여럿" 되묻기는 거의 나오지 않습니다.
- 뜻이 갈리는 말은 되묻지 않고 기준을 밝힙니다.
    - 검토가 표를 하나 고른 뒤에, 그 말이 **기준이 다른 통계가 여럿 있는 말**이어도 되묻지 않고 고른 표의 기준을 답에 붙입니다.
        - "이 숫자는 어느 기관이, 누구를, 언제 기준으로 센 것이다."
        - EX : "서울 가구 수"
            1. 검토가 인구총조사의 가구 표를 고릅니다.
            2. "가구"는 주민등록 세대로도 셀 수 있지만 되묻지 않습니다.
            3. 표 주석에서 "일반가구를 대상으로 집계. 집단가구 및 외국인가구 제외"를 뽑습니다.
            4. 답변에 기관 · 조사 이름과 함께 이 줄이 붙습니다.

## 1. 전체 흐름

화면은 `/ask`만 부릅니다. 수치 경로가 먼저 받고, 사전에 없는 지표일 때 통계표 찾기로 넘어옵니다. 아래는 통계표 찾기 안의 흐름입니다.

새 질문이 오면 두 갈래가 동시에 돕니다.

**갈래 가: 질문 전체로 표 찾기**

| 단계 | 하는 일 | 누가 |
| --- | --- | --- |
| 조건 추출 | 질문에서 주제, 재작성 검색어, 대상, 분류, 항목, 성별, 지역, 연도, 빼 달라는 말을 뽑음 | LLM ① |
| 보정 | 연도 · 상대 시점 · 나이 표현을 규칙으로 다시 읽고, 질문에 근거가 없는 조건을 걸러냄 | 코드 |
| 검색 | 키워드 점수 + 임베딩 점수 + 조건 확인 가감점으로 표 2,364개의 처음 순위를 냄 | 코드 (임베딩은 CLOVA) |
| 상태 판단 | 되물을지, 표 묶음 안에서 어느 표(대상 · 성별 · 판)인지 정함. 범위 밖 거절은 여기서 하지 않고 검토에 맡김 | 코드 |
| 검토 | 상위 후보 8개를 다시 보고 최종 표를 고르거나(리랭커 노릇) "맞는 표 없음"으로 거절 | LLM ③ |
| 함께 볼 표 | 통계가 여러 표로 나뉘어 있으면 나머지 표를 덧붙임 (조건이 맞을 때만) | LLM ④ |

**갈래 나: 지표가 여럿인 질문 대비**

| 단계 | 하는 일 | 누가 |
| --- | --- | --- |
| 계획 | 질문을 지표로 나눔 ("출생아 수와 혼인 건수" → 2개) | LLM ② |
| 계획 보정 | 근거 없는 조건 삭제, 빠진 지표 채우기 | 코드 |
| 지표별 검색 | 지표가 2개 이상이면 지표마다 따로 검색 (LLM 없음, 임베딩만) | 코드 |

**마지막: 답변 만들기 (코드)**

추천 통계표, 조건 확인(✔ / ✘), 주석에서 뽑은 안내(기준일, 대상 범위 등), 함께 볼 표, 바로가기를 문장으로 만듭니다.

## 2. LLM이 맡는 일과 그렇게 만든 이유

|  | 맡는 일 | 왜 LLM인가 | 코드가 잡아 주는 것 |
| --- | --- | --- | --- |
| ① 조건 추출 | 일상어를 조건으로 옮김 | "아이를 몇 명 낳는지" 같은 말은 규칙으로 못 읽습니다. 재작성 검색어가 임베딩 검색을 표 이름 쪽으로 당겨 줍니다 | 연도 · 지역 · 나이는 규칙이 다시 읽습니다. 질문에 없는 조건은 걸러냅니다 |
| ② 계획 | 지표 나누기 | 한 번의 검색으로는 여러 표를 못 찾습니다. 필요한 표를 찾은 비율이 77% → 95%로 올랐습니다 | 같은 표 묶음이면 지표 하나로 합칩니다. 계획이 실패해도 갈래 가의 결과는 그대로 나갑니다 |
| ③ 검토 | 상위 후보 중 최종 표 고르기, 범위 밖 거절 | 글자 점수로는 "전용 표와 넓은 표", "답할 수 없는 질문"을 못 가립니다 | 후보 밖의 표는 고를 수 없게 출력 형식으로 막습니다. 지역을 되묻는 중에는 표를 바꾸지 못하게 합니다 |
| ④ 함께 볼 표 | 나뉜 표 알아채기 | "배우자 = 남편 + 아내"는 뜻을 알아야 합니다 | 같은 조사이고 이름이 거의 같은 표만 보여 줍니다 |

**코드가 하는 것**: 처음 순위 계산, 조건 확인(✔ / ✘) 매기기, 묶음 안의 표(대상 · 성별 · 판) 고르기, 되물을지 판정. 같은 질문에 같은 결과가 나와야 하는 부분입니다.

**LLM이 코드보다 우선하는 곳**

| 무엇 | 어떻게 |
| --- | --- |
| 최종 표 | 코드의 1위가 아니라 검토가 고른 표로 답합니다 (Gemma일 때) |
| 범위 밖 거절 | 코드는 점수로 거절하지 않고, 검토가 "맞는 표 없음"이라 할 때 거절합니다 |
| 낱말 ✘ | 검토가 "모두 충족"으로 고른 표에는 코드가 매긴 항목 · 분류 · 대상 ✘를 붙이지 않습니다(질문 "외국인 노동자", 표 "외국인 근로자"). 연도 · 지역 단위 · 성별 ✘와 판 메모는 그대로 둡니다. ✘가 지워진 표는 숫자 계산으로 넘어갑니다 |

**모델에 따라 다른 점**

|  | Gemma 4 31B (기본) | HCX-007 (Gemma 서버가 꺼졌을 때) |
| --- | --- | --- |
| 검토 | 고른 표로 실제로 바꿈 | 거절만 함. 표는 검색 1위 그대로 |
| 이유 | 바꾸게 했을 때 정답이 늘었습니다 (408문항 323 → 363) | 바꾸게 하면 같은 조사의 형제 표로 잘못 바꿔 손해였습니다 |
| 함께 볼 표 | 동작 | 건너뜀 (같은 요청 10개 모두에 표를 덧붙여서 못 씁니다) |
| 응답 시간 | 질문당 약 12초 | 약 4초 |

## 3. 되묻기

되묻기는 다섯 가지이고, 모두 LLM이 아니라 규칙으로 판정합니다.

| 어디서 | 언제 | 무엇을 묻나 |
| --- | --- | --- |
| 수치 경로 앞단 | "우리 동네"라고 했는데 지역이 없음 | 시 · 군 · 구 이름 |
| 수치 경로 앞단 | "~에서 이사한"인데 범위를 말하지 않음 (언어의 모호함 중 일부) | 지역 안에서의 이사도 포함할지 |
| 통계표 찾기 | "우리 구"라고 했는데 검색 1위가 특정 시도 전용 표 | 같은 꼴의 시도별 표 중 어느 지역인지 (질문에서 "동구"라고 했을 때, 동구가 부산 · 울산 등 여러 지역에 있는데 표가 부산 전용 표인 경우) |
| 통계표 찾기 | **1 · 2위 표 묶음의 점수 차가 0.005 미만** | 표 이름을 선택지로 |
| 통계표 찾기 | 표 묶음 안에서 대상이 갈리는데 질문에 없음 | 대상 (성별 · 판은 기본값이 있어 같이 보여 주기만 함) |

- 비슷한 표를 되물을 때, 표마다 무엇이 다른지 한 줄씩 붙입니다.
- EX : 외국인주민 표와 인구총조사 외국인 표의 점수가 거의 같을 때
    - "비슷한 통계표가 여러 개 있습니다. 어떤 자료를 찾으시나요?"
    - ① 시도별 외국인주민 현황 (지방자치단체외국인주민현황, 2015~2024년)
        - → 행정안전부 · 시도 · 분류: 거주외국인별, 성별 · 매년 11월1일 기준
    - ② 성별 외국인 - 시군구 (인구총조사, 2015~2025년)
        - → 국가데이터처 · 시도, 시군구 · 국내거주 외국인을 대상으로 집계

**답을 처리하는 방법**

| 사용자의 답 | 처리 |
| --- | --- |
| "2번", "②", 표 이름의 일부 | 그 표로 답 |
| "아무거나", "알아서" | 1순위로 답 |
| "여자", "2010년" | 앞 질문에 조건을 더해 다시 검색 |
| 그 밖의 말 | 답만으로 새로 검색하고, 범위 밖이면 앞 질문에 붙여 다시 검색 |

되묻기는 최대 2번입니다.

## 4. 말의 모호함을 어떻게 다루나

질문의 말이 여러 뜻으로 읽힐 때 쓰는 방법은 네 가지입니다.

| 방법 | 언제 쓰나 |
| --- | --- |
| 묻는다 | 어느 뜻이냐에 따라 숫자가 크게 달라지고, 기본값을 정하기 어려울 때 |
| 한 뜻으로 정한다 (규칙 · 사전) | 관행이나 문맥으로 뜻이 정해질 때 |
| 답하고 기준을 밝힌다 | 어느 뜻으로 답해도 틀리지 않을 때 |
| 여러 표를 함께 낸다 | 한 낱말이 여러 표에 걸쳐 있을 때 |

### 4-1. 이사 범위: "서울에서 이사 간 사람"

서울 밖으로 나간 사람만인지, 서울 안에서 옮긴 사람도 포함인지가 갈립니다. **이 경우는 묻습니다.** 수치 경로 앞단의 규칙이 맡습니다.

> 이사 범위를 확인할게요. 해당 지역 안에서 이사한 경우도 포함할까요, 그 지역 밖으로 나간 경우만 볼까요?
>
> ① 지역 안에서의 이사도 포함 ② 지역 밖으로 나간 이사만

문장별 판정 (11/17 코드로 확인)

| 질문 | 판정 | 이유 |
| --- | --- | --- |
| 서울에서 이사 간 사람 몇 명이야? | 묻는다 | 범위를 말하지 않음 |
| 수원에서 이사한 사람 몇 명이야? | 묻는다 | 범위를 말하지 않음 |
| 수원에서 이사 **나간** 사람 몇 명이야? | 묻지 않는다 | "나간"이 밖으로 나간 것만을 뜻함 |
| **전국**에서 이사한 사람 수 | 묻지 않는다 | 전국은 안팎의 구분이 없음 |
| 서울에서 **부산으로** 이사한 사람 | 묻지 않는다 | 도착지를 말함 |
| 서울에서 **다른 지역으로** 이사한 사람 | 묻지 않는다 | 범위를 말함 |
| 서울**로** 이사 온 사람 | 묻지 않는다 | 들어온 사람을 묻는 다른 질문 |

답은 정해진 문구가 아니라 핵심 낱말로 읽습니다. "밖으로 나간 사람만", "다 포함", "둘 다요", "2번", "서울 안에서 옮긴 것도요"를 모두 알아듣습니다. 두 번 물어도 못 알아들으면 기본값으로 답하고 그 사실을 알립니다.

고른 뒤에는 전출자 수 · 이동자 수 지표로 숫자를 답합니다. 계산하지 못하면 통계표 찾기로 넘기는데, 이때 넘어오는 문장으로 맞는 표(시군구별 이동자수)를 찾는 것을 확인했습니다.

**한계**: 규칙이 "~에서 … 이사"라는 꼴만 잡습니다. "서울을 **떠난** 사람", "서울에서 **빠져나간** 인구"는 "이사"라는 말이 없어 이 규칙에 걸리지 않고 묻지 않습니다. 이 두 문장은 "밖으로 나간 것"이라는 뜻이 분명해 큰 문제는 아니지만, "이사"가 아닌 다른 낱말의 범위 모호함은 다루지 않습니다.

### 4-2. 그 밖의 모호함과 처리

| 모호함 | 예 | 처리 | 방법 | 어디서 |
| --- | --- | --- | --- | --- |
| 지역이 빠짐 | "우리 동네 인구" | 지역을 묻는다 | 규칙 | PR #133 |
| 같은 이름의 지역이 여럿 | "강서 인구", "고성 인구" | 어느 곳인지 묻는다. "서울 강서"처럼 시도를 말했으면 그 시도 안에서 찾는다 | 규칙 | PR #145 |
| 지역처럼 보이는 다른 낱말 | "**고령** 인구 비율", "우리 **구로** 이사 오는" | 지역으로 읽지 않는다 | 규칙 + 프롬프트 | PR #145, #138 |
| 연도를 말하지 않음 | "서울 외국인주민 수" | 자료의 마지막 해로 답한다. LLM이 짐작한 연도는 버린다 | 규칙 | PR #145 |

## 6. 되묻기 개선 제안(표 찾기 전과 후로 나누기)과의 비교

제안의 "현재 상태"는 주말 수정 전을 기준으로 적혀 있어, 지금과 다른 부분이 있습니다.

**"현재 상태"에서 달라진 것**

| 적힌 내용 | 지금 |
| --- | --- |
| 표 찾은 뒤: 표가 여러 개면 표 이름을 선택지로 준다 | Gemma에서는 거의 일어나지 않습니다. 검토가 고릅니다 |
| "외국인"을 외국인주민으로 바로 해석한다 | 지금도 바로 답합니다. 일부러 그렇게 정했고, 답에 대상 범위를 밝힙니다 |
| 계산 결과가 같다면 중복 정답 | 지금은 확인할 방법이 없습니다. 통계표 찾기는 값을 읽지 않고, 값을 읽는 수치 경로는 사전에 정해진 지표만 계산합니다 |

## 7. 팀과 정할 것

1. **값을 비교해서 묻기.** 통계표 찾기와 값 조회를 잇는 일이라 수치 경로와 같이 설계해야 합니다.
2. **화면.** 응답에 새 칸이 둘 생겼는데 화면은 아직 읽지 않습니다.
    - `together`: "함께 볼 표"(예: 외국인 아내 표 + 남편 표)가 지금은 답변 문장으로만 나옵니다. 이 표도 카드로 보여 줄지 정해야 합니다.
    - `clarify.families[].diff`: 되묻기 선택지의 차이 줄입니다. 되묻기일 때 화면은 답의 첫 줄만 말풍선에 쓰고 선택지는 버튼으로 그리므로, 버튼에 이 줄을 더해야 보입니다.

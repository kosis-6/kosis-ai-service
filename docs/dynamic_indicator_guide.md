# 동적 지표 계산 모듈: 연산 규칙, 검증, 캐시, 성능

## 한눈에

- 지표 사전(44개)에 없는 지표도 **적재된 통계표의 칸 값으로 계산해 숫자로 답합니다.** 예전에는 표 안내로 끝났습니다.
- **LLM은 숫자를 만들지 않습니다.** 표의 칸은 코드가 규칙으로 고르고, 계산은 조회 엔진(`lookup.py`)이 DB 값으로 합니다. 이 모듈이 새로 부르는 LLM 호출은 없습니다.
- 칸을 확실히 고르지 못하거나 검증에 걸리면 **숫자를 내지 않고** 되묻거나 통계표를 안내합니다.
- 한 번 계산한 지표는 계산 방법(표·칸)을 저장해 두고, 다음에는 통계표 찾기(HCX 3회)를 건너뜁니다. **수 초 → 0.1초 이하.**
- 원인·예측 질문, 표의 구간과 맞지 않는 조건은 답변 불가로 돌리고 대신 볼 수 있는 통계·구간을 안내합니다.

| 파일 | 하는 일 |
|---|---|
| `backend/app/services/dynamic_indicator.py` | 칸 고르기, 계산 계획 만들기, 검증, 분류 안의 합·비교·순위 |
| `backend/app/services/plan_cache.py` | 계산 방법 캐시 (`app.dynamic_plans`, 마이그레이션 0018) |
| `backend/app/services/memory_cache.py` | 서버 메모리 캐시 (LRU + TTL, 계산 방법·대화 상태) |
| `backend/app/services/qa.py` | 원인·예측 질문 거절, 지원하지 않는 조건, 근거 판단 (`grounded`) |
| `backend/app/services/lookup.py` | 값·비교·추이·순위·구성비 계산, 맞는 구간 없음 (`band_mismatch`) |
| `backend/app/services/ask_session.py` | 언제 바로 계산을 시도할지 (사전에 없음 / 근거 없음 / 옛 연도) |

## 1. 처리 흐름

```text
질문 ─ 질문 해석 (qa.understand + qa.correct)
  │
  ├─ 원인·정책 질문 ("~ 덕분에 늘었어?")          → 답변 불가 + 그 지표 추이 표 안내   (causal_question)
  ├─ 예측 질문 ("앞으로 오를까?", 미래 연도 없음)   → 답변 불가 + 추이 표 안내          (prediction_question)
  │
  ├─ ① 지표 사전에 있고 질문에 그 이름·별칭이 있음 → 기존 계산
  │       ├─ 사전 표가 지원하지 않는 조건 (체중 3.2kg, 결혼 1년 반) → 맞는 구간 없음 (band_mismatch)
  │       └─ 사전 표보다 옛 연도 (1980년 이혼 건수) → ②로 그 연도가 있는 표를 찾음. 못 찾으면 기간 밖 안내
  │
  ├─ ② 사전에 없음 / 사전 지표인데 근거 없음 ("통학 인구"를 총인구로 고름)
  │       계산 방법 캐시에 있음 → 저장한 표로 바로 (통계표 찾기 생략)
  │       없음 → 통계표 찾기 → 후보 표(순위대로 3개)마다 칸 고르기 → 검증 → 계산
  │         ├─ 계산됨                 → 숫자 + 계산식·쓴 표·칸 + "바로 계산했다" 알림
  │         ├─ 칸 하나를 못 고름      → 되묻기 (table_cell)
  │         ├─ 구간이 안 맞음         → 맞는 구간 없음 + 볼 수 있는 구간
  │         └─ 그 밖                  → 통계표 안내 (근거 없는 사전 답은 돌려주지 않음)
  │
  └─ ③ 통계표 찾기도 인구 분야 표를 못 찾음 → 거절 (out_of_scope)
```

- 바로 계산은 **통계표 찾기가 `ok`이고 함께 볼 표(`together`)가 없을 때만** 합니다. 일부 일치(`partial_match`)는 어긋난 조건이 연령뿐일 때만 계산합니다(연령은 조회 엔진이 연령 칸으로 직접 처리).
- 후보 표는 순위대로 3개까지 보되, 통계표 찾기가 조건 ✘로 표시한 표는 건너뜁니다. 정답 표가 1순위가 아닌 경우가 있어 1순위만 쓰지는 않습니다.
- 옛 연도 찾기는 지표의 뜻이 사전으로 정해져 있어서, 통계표 찾기가 "비슷한 표 여럿"(`ambiguous`)으로 끝나도 그 후보로 계산해 봅니다.

## 2. 칸 고르기

표의 분류(항목, 지역, 성별, 연령, 그 밖)마다 칸 하나를 고릅니다.

| 분류 | 규칙 |
|---|---|
| 지역 | 조회 엔진이 질문마다 고릅니다 (`region_code_map`) |
| 성별 | 질문 해석의 성별 → 남자·여자 칸. 성별이 항목에 들어 있는 표도 처리 (예: 1인가구·남자·여자) |
| 연령 | 질문의 연령 구간 → 조회 엔진의 연령 칸 (말하지 않으면 합계). 칸 이름으로 연령을 읽습니다(코드 번호로 읽지 않음) |
| 그 밖 | 칸 이름이 질문에 그대로 있으면 그 칸 (공백·기호 무시, 긴 이름 우선, 끝의 "-계"는 떼고도 맞춤) |

- 표가 쓰는 말과 같은 뜻의 일상어는 맞추기 전에 바꿉니다: "출퇴근·출근" → "통근".
- 한 분류의 세부 칸을 모두 말하면(통근 + 통학) 그 분류의 합계를 씁니다.
- **질문의 말과 맞는 칸이 하나도 없으면 계산하지 않습니다.** 표의 다른 값을 엉뚱한 질문의 답으로 내지 않기 위해서입니다.
- 통계표 찾기가 뽑은 조건이 칸에 모두 반영돼야 합니다.
  - 찾는 값(예: "미혼")이 고른 칸에 없으면 계산하지 않습니다.
  - 빼 달라는 말이 있으면 계산하지 않습니다 (합계 칸에 그 대상이 들어 있음).
  - 구성비가 아닌데 "~별"을 물으면 계산하지 않습니다.
- "노년부양비"의 "노년"처럼 말에서 짐작한 연령은, 그 말이 고른 칸 이름 안에 있을 때만 지표 이름의 일부로 보고 무시합니다.

### 말하지 않은 분류의 기본값

| 경우 | 기본값 |
|---|---|
| 합계가 '전부'라는 뜻인 분류 (성별·연령·국적·교육정도·혼인상태·가구원수 등, `SAFE_TOTAL`) | 합계 |
| 그 밖의 분류 (예: 특성별처럼 여러 기준이 섞인 분류) | 합계 + 답에 "합계로 계산했다"고 알림 |
| 합계가 없는 장래추계 시나리오·가정 | 중위 추계 + 알림 (지표 사전과 같음) |
| 합계가 없고 칸이 8개 이하 | 되묻기 (`table_cell`) |
| 합계가 없고 칸이 8개보다 많음 | 표 안내 |

## 3. 연산

| 연산 | 언제 | 예 | 계산 |
|---|---|---|---|
| 값 | 기본 | 2020년 서울 1인 가구 수 | 고른 칸 |
| 지역 비교·추이·순위·증감 | 질문 종류가 비교·추이·순위 | 서울과 부산 1인 가구 수 | 같은 칸을 지역·연도만 바꿔 (기존 함수) |
| 비율 | "~ 중 ~ 비율·비중·%" | 서울 1인 가구 중 여성 비율 | 질문에서 고른 칸 하나 ÷ 같은 분류의 합계 × 100 |
| 구성비 | 질문 종류가 구성비이고 "~별"을 말함 | 1인 가구 연령별 구성 | 칸마다 ÷ 합계 |
| 분류 안의 합 | 한 분류에서 칸이 둘 이상 맞고 "~나·합·모두·또는" | 걸어서나 자전거로 통근·통학 | 칸들의 합 |
| 분류 안의 비교 | 칸이 둘 맞고 "비교·차이·몇 배·보다" | 걸어서와 자전거 차이 | 차이와 배수 |
| 분류 안의 순위 | "top3·순위·가장 많이"이고 지역이 아니라 분류를 물음 | 교통수단 top3 | 세부 칸끼리 정렬 (소계·합계 칸 제외) |

- 다른 표끼리 나누는 계산(세대당 인구 = 인구 ÷ 세대 수)과 부분 ÷ 부분(성비 = 남 ÷ 여)은 아직 없습니다.
- 지역 순위 질문("1인 가구가 가장 많은 시도")은 분류 안의 순위가 아니라 지역 순위입니다.

## 4. 검증 (하나라도 걸리면 숫자를 내지 않음)

| 검증 | 내용 |
|---|---|
| 칸 존재 | 고른 칸 코드가 표에 실제로 있는가 |
| 분자 ≤ 분모 | 비율·연령 구간 합·구성비·분류 안의 합을 계산하기 전에, **표의 모든 지역·연도에서** 분자(부분의 합) ≤ 분모(합계)인가. 겹치는 묶음 칸을 두 번 세는 것도 막습니다 |
| 추계 표 | 장래추계 표는 물은 연도가 모두 실적 자료의 마지막 해 뒤일 때만. 연도를 말하지 않거나 실적과 섞인 기간이면 쓰지 않음 |
| 값 존재 | 계산은 됐는데 값이 비어 있으면(비공개 `*`·결측) 다음 후보 표 |
| 숫자 조건 | 질문의 숫자 조건(3.2kg, 1년 반)이 표의 구간 분류에 해당하는데 맞는 칸이 없으면 맞는 구간 없음 |
| 고정 조건 | 다음 턴에서 정의를 만들 때 고정한 조건(비율의 성별, 구성비, 추계 표의 미래 연도)이 바뀌면 정의를 다시 만듦 |

## 5. 답변 불가와 안내

| status | 언제 | 답 |
|---|---|---|
| `causal_question` | 원인·정책 효과 질문 | "통계 수치만으로 판단할 수 없어 답할 수 없습니다. 대신 ○○의 변화는 아래 통계표에서 확인할 수 있습니다." (숫자 없음) |
| `prediction_question` | "앞으로·전망·오를까" 등, 미래 연도 없음 | 위와 같은 안내 + 미래 연도를 넣으면 장래추계로 답한다는 안내 |
| `prediction_question` | 시군구의 미래 연도 (2040년 해운대구) | 장래추계는 시도까지만 → 속한 시도(부산) 추계값을 대신 보여 줌 |
| `band_mismatch` | 연령 구간이 표의 구간과 맞지 않음 | "대신 볼 수 있는 구간: 60~64세, 65~69세" |
| `band_mismatch` | 사전 표가 지원하지 않는 조건, 숫자 조건이 구간과 맞지 않음 | "'체중' 조건으로 나뉘어 있지 않습니다. 대신 조건 없는 전국 출생아 수는 확인할 수 있습니다" / "볼 수 있는 체중 구간: 2.5~2.9㎏, 3.0~3.4㎏ …" |
| `out_of_scope` | 통계표 찾기도 인구 분야 표를 못 찾음 | 범위 밖 거절 |
| `tables` | 그 밖에 계산하지 못함 | 통계표 안내 |

미래 연도를 말한 질문("2040년 서울 인구는 몇 명이 될까요?")은 예측 질문으로 보지 않고 지금처럼 장래추계로 답합니다.

## 6. 근거 없는 사전 지표

질문에 고른 사전 지표의 이름·별칭이 없으면(`parsed.grounded = false`), HCX가 비슷한 다른 지표를 고른 것일 수 있습니다.

- 예: "서울 1인 가구 중 여성 비율"을 총인구 성별 구성으로, "통학 인구"를 총인구로.
- 총인구는 별칭 "인구"가 넓어서, "인구" 바로 앞의 말이 지역·성별·연령·전체가 아니면("통학", "외국인", "다문화") 근거 없음으로 봅니다.
- 근거 없음이면 바로 계산을 시도하고, 안 되면 **원래 사전 답을 돌려주지 않고** 되묻기나 통계표 안내로 답합니다. 기간 밖 안내도 같습니다.
- 지표가 없는 질문(원인 질문 등)은 판단하지 않습니다.

## 7. 계산 방법 캐시

| 항목 | 내용 |
|---|---|
| 저장 | 바로 계산이 성공하면 지표 표현(공백·기호 뺀 것)을 키로, 쓴 표를 `app.dynamic_plans`에 |
| 저장 안 함 | 지역·연도·숫자, 사전 지표 이름이나 연도·지역이 섞인 표현("2020년 서울"), 되묻기에서 사용자가 고른 칸 |
| 꺼내 쓰기 | 같은 표현이 오면 통계표 찾기를 건너뛰고 그 표로. **칸 고르기·검증은 매번 다시** (표가 다시 적재돼도, 질문 조건이 달라도 맞는 칸) |
| 버리기 | 그 표로 답하지 못하면(기간 밖 등) 쓰지 않고 통계표 찾기로. 90일 동안 안 쓴 계획은 지움 |
| 서버 메모리 | 키별 계획을 512개까지 10분 동안 (`MEMORY_CACHE=0`이면 끔) |
| 관리 | `GET /admin/dynamic-plans` (많이 쓴 순, 사전에 올릴 후보), `DELETE /admin/dynamic-plans/{id}` |

## 10. 한계와 다음 단계

- **같은 질문의 답이 실행마다 바뀔 수 있습니다.** HCX 해석과 통계표 찾기 결과가 실행마다 달라, 같은 질문이 숫자·표 안내·되묻기로 바뀝니다. 검증 덕분에 틀린 숫자는 막지만 답의 형태는 흔들립니다.
- **일상어 연결이 없습니다** (2단계 LLM 보조): "자가용" → "승용차 소형 승합차", "낮·밤" → "주간·상주" 같은 말은 글자로 맞지 않아 계산하지 못합니다.
- **다른 표끼리의 계산이 없습니다** (3단계): 세대당 인구, 인구 1,000명당 율.
- 옛 연도 표는 지금 정의와 다를 수 있습니다(예: 2006년 "거주외국인" ≠ 지금의 "외국인주민"). 사전에 정식 출처로 넣으면 차이를 주의 문구로 적을 수 있습니다.
- 통계표 찾기가 "비슷한 표 여럿"으로 끝나면 일반 질문은 계산하지 않습니다(정확성 우선).

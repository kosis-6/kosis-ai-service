## 1. "그중 여성은?"이 성별을 빼고 전체 값을 답함

| | |
|---|---|
| 대화 | T1 "2020년 서울 1인 가구 수는?" → T2 **"그중 여성은?"** (개발셋 R01-T2) |
| 챗봇 답 | 2020년 서울특별시의 1인 가구 수는 1,390,701가구입니다. |
| 정답 | **739,702가구** |
| 정답 근거 | DT_1PR2002 「성별/연령별/혼인상태별 1인가구(일반가구)-시군구」 2020, 서울특별시 · 여자 · 연령 합계 · 항목 1인가구 (계 1,390,701 중 여자 739,702 = 53.19%) |

관찰
- 질문 해석은 맞다: `parsed.sex = "여"`
- 그런데 답은 DT_1JC1502 「가구원수별 가구 - 읍면동」에서 냈다. 이 표에는 성별 칸이 없어 성별 조건이 조용히 빠졌다
  (`figure.conditions.sex = None`, 라벨도 "2020년 서울특별시 1인 가구 수")
- 같은 대화에서 "그중 여성 **비율**은?"(R07-T2)은 DT_1PR2002로 53.19%를 맞게 낸다

기대: 성별 조건이 있으면 성별 칸이 있는 표(DT_1PR2002)로 가거나, 없으면 "이 표에는 성별 구분이 없다"고 알린다.
성별을 버리고 전체 값을 답하면 안 된다.

## 2. "2025년 외국인주민 수"가 입국연도 2025 항목을 답함

| | |
|---|---|
| 대화 | T1 "2025년 서울 인구는?" → T2 "2024년 서울 혼인 건수는?" → T3 **"2025년 외국인주민 수는?"** (R06-T3) |
| 챗봇 답 | 2025년 서울특별시의 2025 수는 46,385명입니다. |
| 확인된 문제 | 조회 연도를 입국연도 항목으로 적용했다. 외국인주민현황에서 질문한 2025년은 적재 범위 밖이다. |
| 대체 후보 | 인구총조사 기준 서울 외국인 **368,500명** (전국 2,109,057명) |
| 대체 후보 근거 | DT_1JA1607 「성, 연령 및 입국연도별 외국인 - 시도」 2025, 항목 "외국인 - 계" · 서울특별시 · 성별 계 · 연령 합계 |

관찰
- DT_1JA1607의 항목(c0)은 **입국연도**다: 외국인 - 계, 1989년이전, …, 2010, 2011, …, **2025**
- 질문의 "2025년"을 연도가 아니라 항목 "2025"(2025년에 입국한 외국인)로 골랐다: 46,385명 = 서울 외국인 중 2025년 입국자
- 질문 해석: `parsed.indicator = "2025 수"`, `parsed.term = "2025년"`. 지표 이름이 연도에서 만들어졌다
- 라벨 "2025 수"가 보고서 요약에도 그대로 들어간다 ("2025년 서울특별시의 2025 수는 46,385명이었습니다")

참고
- "외국인주민"은 행정안전부 「외국인주민현황」 용어다. DB에 있는 DT_110025_A030_A 등은 **2022~2024년**만 적재돼 있어
  2025년 값이 없다. 인구총조사는 집계 대상이 다른 통계다. 기준 차이를 밝히고 대체 값을 줄지,
  외국인주민현황의 적재 범위인 2024년까지를 안내할지는 미결정이다.
- 지역은 앞 턴의 서울을 이어 받았다 (이어 묻기 규칙상 맞음)

## 3. 주민등록 인구(실측)가 추계값으로 표시됨

| | |
|---|---|
| 질문 | **2025년 서울 인구는?** (R06-T1) |
| 챗봇 답 | 2025년 서울특별시의 총인구는 9,299,548명입니다. (값은 맞음) |
| 정답 | 9,299,548명, **실측** (DT_1B04006 주민등록인구, 2025년 12월 31일 기준) |
| 문제 | `figure.is_projection = True` → 보고서 요약에 "2025년 서울특별시의 총인구는 9,299,548명으로 **예상됩니다**", 비교 검사도 추계로 다룸 |

원인 (확인함)
- `app/services/figure.py`의 `is_projection()`이 답의 안내문에 `PROJECTION_WORDS = ("장래추계", "추계값")`가 있으면 추계로 본다
- 이 답의 안내문: "※ 인구는 기준이 여럿입니다. 주민등록인구(내국인)로 답했습니다. 외국인을 포함하는 인구총조사 인구(11월 1일 기준)나
  **장래추계**인구(7월 1일 기준)와는 값이 다릅니다"
- "추계와 다르다"는 안내문의 단어가 걸렸다. 주민등록인구로 답하는 모든 총인구 답에서 같은 일이 생긴다

## 4. 이어 묻는 연도가 실측 범위를 넘으면 추계표로 가지 않음

| | |
|---|---|
| 대화 | T1 "2020년 서울 1인 가구 수는?" → T2 **"2040년에는 얼마나 될까?"** (R10-T2) |
| 챗봇 답 | 1인 가구 수 자료는 2015~2025년만 있습니다. 2015~2025년 사이 연도로 다시 질문해 주세요 (가장 가까운 2025년 자료가 있음). (status `out_of_range`) |
| 정답 | **1,842,002가구** (추계) |
| 정답 근거 | DT_1BZ0506 「가구주의 연령/가구원수별 추계가구_시도」 2040, 항목 1인 · 서울특별시 · 가구주 연령 합계 |

관찰
- 같은 값을 한 문장으로 물으면("2040년 서울 1인 가구 수는?") 1,842,002가구를 추계로 맞게 답한다 (보고서 에이전트의 ask_stat 조회에서 확인)
- 이어 묻기에서는 T1의 표(DT_1JC1502, 2015~2025)를 그대로 쓰고 연도만 바꿔 범위 밖으로 끝난다

기대: 바뀐 연도가 실측 표 범위를 넘고 추계표가 있으면 추계표로 다시 찾는다 (한 문장 질문과 같은 결과).

## 참고: 버그 아님 (되묻기가 맞는 동작)

"2025년 서울 부산 대구 인천 광주 대전 1인 가구 수 비교"는 `ambiguous_region`('광주')으로 되묻는다.
광주광역시 · 경기도 광주시가 둘 다 있으므로 질문 경로는 그대로 둔다.
문제는 보고서 에이전트 쪽이다: 이 되묻기를 받고 사용자에게 묻지 않고 스스로 질문을 바꿔 다시 조회하다가
대전을 빠뜨리거나 결과에 나온 구 이름(광산구 · 서구)으로 바꿔 실패가 이어졌다 (개발셋 R16-T1). 에이전트 쪽에서 다룬다.

## 다시 확인하는 법

원자료가 적재된 개발 DB에서 사례 1의 비교값을 확인한다. 저장소 루트에서 실행한다.

```bash
docker compose exec -T db sh -c 'psql -X -v ON_ERROR_STOP=1 -U "$POSTGRES_USER" -d "$POSTGRES_DB"' <<'SQL'
SELECT v.period, i.name AS item, r.name AS region, s.name AS sex, a.name AS age,
       m.name AS marital_status, v.value, v.flag
FROM raw.stat_value v
JOIN catalog.stat_table t ON t.tbl_key = v.tbl_key
JOIN catalog.stat_code i ON i.code_key = v.item_key
JOIN catalog.stat_code r ON r.code_key = v.c1
JOIN catalog.stat_code s ON s.code_key = v.c2
JOIN catalog.stat_code a ON a.code_key = v.c3
LEFT JOIN catalog.stat_code m ON m.code_key = v.c4
WHERE t.tbl_id = 'DT_1PR2002' AND v.period = 2020 AND v.prd_se = 'A'
  AND i.name IN ('1인가구', '1인 가구')
  AND r.name = '서울특별시' AND s.name = '여자' AND a.name IN ('계', '합계', '전체')
  AND (m.code_key IS NULL OR m.is_total OR m.name IN ('계', '합계', '전체'));
SQL
```

확인 당시 전체 혼인상태의 값은 739,702가구였다. 아래 대화 재현 명령에는 개발셋 시트에서 내보낸 CSV가 필요하다.

```bash
cd backend
uv run python -m scripts.eval_report_agent --csv eval/report_scenarios_multiturn_v0.3.csv --only R01,R06,R10
```

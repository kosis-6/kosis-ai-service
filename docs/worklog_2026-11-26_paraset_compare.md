## 3. 변형에서만 틀린 17건 (코드 ② 기준)

### ① 되묻기 뒤 지역 답을 못 읽음 — 4건 (P-116 · 121 · 124 · 125)

- 사용자 답이 원문과 **다르다**. 원문 "대구 수성구", 변형 "수성구, 대구요".
- `question_clarify.region_reply`는 답에서 지역 이름을 지운 뒤 남은 말이 조사뿐이어야 지역으로 받는데, **쉼표(,)를 지우지 않는다**. `bare_region`도 "수성구, 대구"를 통째로 찾아 `unknown_region`. 그래서 첫 질문을 그대로 다시 보내 같은 되묻기를 한다.
- 변형셋 v2의 P2-123 "삼척시요, 강원도", P2-125 "구미시요, 경북"도 같은 모양이다. 쉼표 없는 v2 답("서울 영등포구요", "충북 청주요", "안산이요" 등)은 모두 읽는다.

| 사용자 답 | `region_reply` | `bare_region` → 찾기 |
|---|---|---|
| 대구 수성구 | 대구 수성구 | - |
| 수성구, 대구요 | None | "수성구, 대구" → unknown_region |
| 순천시요, 전남 | None | "순천시요, 전남" → unknown_region |
| 삼척시요, 강원도 (v2) | None | unknown_region |

- 고칠 곳: 쉼표 · '요'를 지우고, '구·시, 시도' 순서면 시도를 앞으로 보내 `merge_region`.

## 4. 세진님 분석과 다른 점

- **'우리 동네' 4건**: P1 기록은 "사용자 답은 원문과 같으니 첫 질문의 말이 되묻기 상태에 남긴 조건이 다름"으로 봤지만, 사용자 답이 다르고(쉼표 · 순서 · '요') **답을 읽는 코드**에서 막힌다(3절 ①).
- **구어체 거절 분류 중 P-126 · P-128**: 거절 분류가 흔들린 게 아니라, 사전이 맞는 사유를 냈는데 `grounded=False`로 버려진 것이다(3절 ②).
- **칸 고르기 묶음**: P-033 · 068은 recell로 해결. P-038은 D1로 해결.

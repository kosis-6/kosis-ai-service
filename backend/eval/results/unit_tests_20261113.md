## 테스트 방식

- 실제 DB, HCX, KOSIS, 임베딩, 메일은 부르지 않습니다. 해당 함수를 `monkeypatch`로 가짜로 바꾸고, 표 목록 같은 데이터는 테스트 안에서 작게 만들어 씁니다. 그래서 네트워크와 DB 없이 돕니다.
- API 테스트는 FastAPI `TestClient`로 실제 엔드포인트를 부릅니다.
- `tests/conftest.py`가 요청 로그는 임시 폴더로, 대화 세션은 메모리로 돌립니다. 개발 DB에 흔적이 남지 않습니다.
- 실행 수에는 같은 테스트를 입력만 바꿔 여러 번 돈 것(parametrize)도 들어 있습니다.

## 실행 전에: 의존성 설치

PR #125 이후 `langgraph`가 의존성에 들어왔습니다. 설치되지 않은 환경에서는 `conftest.py`를 불러오다 `ModuleNotFoundError: langchain_core`로 테스트가 아예 시작되지 않습니다. `kiwipiepy`(형태소 분석)가 없으면 검색 테스트 3개가 실패합니다.

```bash
cd backend
uv sync --frozen --inexact   # lock 파일 버전 그대로, 이미 있는 패키지는 지우지 않음
python -m pytest -q
```

`kiwipiepy`가 없으면 서버는 오류 없이 돌지만 검색어에서 조사를 떼지 못합니다("시도별로"가 "시도별"이 되지 않음). 그만큼 검색 품질이 떨어지니, 서버 이미지에도 설치돼 있는지 확인해 주세요.

## 1. 통계표 찾기 — 에이전트 흐름 (`app/agent`)

| 테스트 파일 | 실행 | 결과 |

**확인한 것**
- LangGraph 흐름(`graph.py`)이 기존 `dialog.handle`과 같은 입력에서 같은 결과를 냅니다.
- 계획 가지를 얹어도 기존 결과는 바뀌지 않고 `result["multi"]`만 덧붙습니다.
- 지표가 여럿이면 지표마다 후보 표를 찾습니다. 지표가 하나면 지표별 검색을 하지 않습니다.
- 지표들의 1위 후보가 같은 표 묶음이면 하나로 합칩니다.
- 계획 LLM이 실패해도 답이 나가고, 되묻기 답 턴에는 계획을 부르지 않습니다.
- 계획 보정(`plan.py`)이 질문에 없는 조건은 지우고, 빠뜨린 지표는 채웁니다.
- "작년" 같은 상대 시점은 규칙이 풉니다. 지표마다 그 앞에 쓰인 연도를 가져가고, 지역 수준은 질문을 따릅니다.

**그래서 가능한 기능**
- "합계출산율과 초혼 연령을 시도별로" 같은 질문에서 지표마다 맞는 통계표 카드를 함께 보여 줄 수 있습니다.
- 계획 단계가 실패하거나 꺼져 있어도(`SEARCH_PLAN=false`) 기존 통계표 찾기는 그대로 동작합니다.

**확인한 것**
- 키워드 점수는 단어 희귀도(IDF)로 가중합니다. 하이브리드 점수에서는 임베딩을 기본으로 두고 키워드가 높을 때만 더합니다.
- 조건 검증과 재순위가 동작합니다. 대상은 연도, 지역 수준, 성별, 분류, 값, 대상입니다.
- 표 묶음 안에서 대상·성별로 멤버를, 연도로 판을 고릅니다.
- LLM 최종 검토의 세 모드(filter, pick, resolve)를 확인했습니다. 범위 밖 질문을 거절하는 것도 포함합니다.
- 임베딩이 실패하면 키워드 검색으로 이어 가고, 정답 후보를 거절하지 않습니다.
- 부정어("~말고"), 군더더기 말, 어미가 사전에 잘못 걸리지 않는지 확인했습니다(예: '인지'가 인지 능력으로 걸리는 경우).
- 슬롯 추출은 JSON이 깨지면 1번 재시도하고, 그래도 안 되면 원문 규칙으로 넘어갑니다.
- 되묻기 여러 턴을 확인했습니다. 답으로 확정하고, "아무거나"면 기본값을 쓰고, 2턴을 넘기면 멈춥니다. 되묻는 중에 새 질문이 오면 처음부터 하고, 세션끼리 섞이지 않습니다.

**그래서 가능한 기능**
- 일상어 질문으로 KOSIS 인구 통계표를 찾아 안내합니다. 예: "외국인 아내" → 혼인 귀화자 표.
- 대상이 모호하면 선택지로 되묻고, 화면 버튼이나 글로 답을 받아 표를 확정합니다.
- 인구 통계가 아닌 질문은 범위 밖으로 안내합니다.
- 임베딩 API가 호출 제한에 걸려도 검색이 멈추지 않습니다.

**확인한 것**
- 질문 유형별 답변 문장을 확인했습니다. 유형은 값, 추이, 비교, 순위, 구성비, 원인 질문이고, 조사(은/는)와 단위 표기도 봤습니다.
- 합계를 확인했습니다. 여러 지역 합계(권역 포함)와 기간 합계입니다. 비율 지표는 더하지 않습니다.
- 여러 지역의 추이는 지역마다 계산하고, 여러 지표를 함께 물으면 모두 답합니다.
- 수록 기간 밖 연도는 답변 불가로 두고, 장래 추계값을 대신 보여줍니다.
- LLM의 질문 해석을 코드가 바로잡습니다. 대상은 지표 별칭, 상대 연도, 연령 구간, "과거부터", "최근 N년", 연속 기간, 생활권 이름입니다.
- 이어 묻기를 확인했습니다. 바뀐 조건만 고쳐 다시 계산하고, 지역과 기간을 이어받습니다. 이어받은 조건으로 답할 수 없으면 그 조건을 빼고 다시 답합니다.
- "막대그래프로", "요약해줘"는 다시 계산하지 않고 직전 답을 씁니다.
- 연도 없이 "과거와 비교"라고 물으면 되묻습니다. 그 뒤 "2000년"처럼 짧게 답하면 앞 질문과 합칩니다.
- "최근"을 물으면 KOSIS에 새 연도가 있는지 하루 한 번 확인하고, 있으면 다시 받습니다.
- 계산 함수(증감률, 비중, 구성비, 순위 동률, 몇 배)는 분모가 0이거나 음수인 경우까지 확인했습니다.
- 결과 모양에 따라 차트 종류(꺾은선, 막대, 구성비)를 고르고, 자료가 없는 연도는 비워 둡니다.

**그래서 가능한 기능**
- "2025년 서울과 부산 고령인구 비율 비교", "합계출산율 가장 높은 시도 3곳" 같은 질문에 수치, 차트, 출처 표 카드로 답합니다.
- 수도권, 부울경 같은 권역 합계와 "최근 5년간 총 몇 명" 같은 기간 합계가 됩니다.
- "작년은?", "부산도", "막대그래프로" 같은 이어 묻기가 됩니다.
- 숫자는 LLM이 아니라 코드가 계산하고 문장도 템플릿이라, 수치나 지표 정의가 틀리게 나가지 않습니다.

## 이 테스트가 보장하지 않는 것

- **실제 정답률과 응답 품질**: HCX, DB, KOSIS를 가짜로 바꿔 돌렸으므로 확인하지 않습니다. 골든셋 평가(`backend/eval`)와 PR #125 측정([pr125_agent_eval_20261113.md](pr125_agent_eval_20261113.md))으로 따로 잽니다.
- **실제 KOSIS 응답 형식이 바뀌는 경우**: 테스트에 넣은 예시 응답 기준으로만 확인합니다.
- **프론트 화면 동작**: 백엔드 테스트만 돌렸습니다.

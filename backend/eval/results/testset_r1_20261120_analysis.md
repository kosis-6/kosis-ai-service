# 테스트셋 1차 평가 분석 (2026-11-20)

테스트셋 v1.2 74문항을 처음 돌린 결과다. 68문항(답변 32 · API 답변 14 · 되묻기 8 · 답변 불가 14)을 한 번에 돌리고, 다중 표 6문항(7장)은 나중에 추가해 따로 돌렸다.
테스트셋은 동결 세트라 이 문서에는 **질문 · 정답 · 챗봇 답을 넣지 않고** 처리 경로와 틀린 단계만 적었다 (문항별 표는 부록, 문항 번호만).
고칠 때는 이 집계로 약한 단계를 정하고, 같은 유형을 **개발셋**에서 찾아 고친다 (테스트셋 오답을 보며 고치지 않는다).

- 코드: `feature/basis-defaults` 브랜치 작업본 (기준이 여럿인 말은 되묻지 않고 기본값 + 기준 안내)
- 채점: 숫자 비교를 고친 채점기(`devset_grade.same_number`, 6장)로 다시 채점한 숫자. 채점기 · 챗봇 코드 수정은 이 브랜치에 넣지 않고 따로 올린다
- 실행 두 번 (같은 코드, 같은 DB 상태: API 문항 표는 두 번 모두 적재 전 상태에서 시작)

- ⑤는 세부 구분(구간)이 있는 표가 따로 있는데, 그 구분이 없는 사전 지표로 가서 "그 조건으로 나뉘어 있지 않음"으로 끝났다. 구분이 있는 표로 넘기지 않음 (2건 중 1건은 구간 여러 개 합, 1건은 표에 있는 구간 하나).

## 3. 표는 찾았는데 계산 못 한 8건 (경로 ③)

통계표 찾기는 맞는 표를 골랐고, 표에서 바로 계산하는 단계(`dynamic_indicator`)에서 멈춰 "이 통계표에서 확인하세요"로 끝난 문항이다. 채점기의 '표 찾고도 거절한 원인' 분류.

- **비교 질문은 0/4다.** 챗봇의 비교 답은 두 값과 차이는 말하지만 **배수(몇 배)를 말하지 않는다**. 골든셋 비교 정답은 "차이 · 배수"를 둘 다 요구한다.

| 구성 | 멈춘 단계 | 어떻게 틀렸나 |
|---|---|---|
| 적재 2 | 질문 이해 → 지표 사전 | 질문을 사전 지표 하나로 이해해, 두 지역의 같은 지표를 비교해 답함. 방향(전출지 → 전입지)과 "인구 천 명당"을 놓쳐 두 번째 표로 가지 않음 |
| 적재 2 | 칸 고르기 (분자) | 사전에 없는 비율을 분자 · 분모로 나눠 각각 표에서 계산하는 데까지 감. 분모는 맞았지만 분자에서 세부 조건(가구원수)을 빼고 전체 값을 써서 틀림. LLM 14회 · 87초 |
| API 2 | 통계표 찾기 (후보) | 검색 후보에 맞는 표가 없어 후보 검토가 "맞는 표 없음"으로 거절. 표를 받으러 가지 않음 |
| API 2 | 칸 고르기 | 맞는 두 표를 찾아 KOSIS에서 받는 데까지 성공. 옛 표기 칸 이름(질문의 말과 철자가 다름)을 못 맞추고, 분자 · 분모를 서로 다른 표에서 가져오지 못해 통계표 안내로 끝남 |
| 적재 + API | 질문 이해 → 통계표 찾기 | 질문의 대상을 다른 사전 지표로 잘못 이음. 검색 후보에도 맞는 표가 없어 거절 |
| 적재 + API | 통계표 찾기 (후보 검토) | 후보 검토가 "분자와 분모가 한 표에 같이 있는 표가 없다"며 거절. 두 표를 합쳐 쓰는 경우를 고려하지 않음 |

- **두 표를 합쳐 계산하는 시도는 '사전에 없는 비율을 분자 · 분모로 나눠 계산'하는 경로에서만** 일어났다. 후보 검토는 한 표에 다 있어야 한다고 보고 거절한다.
- API로 표를 받는 것 자체는 성공했다. 막힌 곳은 받은 뒤의 칸 고르기와, 받기 전의 후보 검토다.
- 채점기 수정 전에는 1문항이 맞음으로 잡혔다 (6장의 "5세" 오판).

## 7-1. 챗봇 계산의 반올림 순서 (다음 회차에 반영)

이번 결과를 정리하며 챗봇 계산 코드에서 찾은 것. 이번 점수에는 영향이 없었지만(해당 경로까지 간 문항이 없음) 다음 회차부터 결과가 달라질 수 있다.

- 비율 · 지표 값을 소수 둘째 자리로 **먼저 반올림한 뒤** 그 값으로 차이 · 증감률 · 배수를 계산하는 곳이 있었다:
  두 표로 만든 비율(`cross_indicator`)의 추이 · 비교, 표 칸으로 계산한 비율(`lookup`)의 추이 · 비교, 지표 사전 비교(`indicators.compare`)의 차이.
  지표 사전 추이(`indicators.trend`)는 11/18에 이미 원값 계산으로 고쳐져 있었다.
- 1% 안팎의 작은 비율에서 크게 틀어진다. 예: 1.176583% → 1.879596%의 증감률은 59.75%인데, 1.18% → 1.88%로 계산하면 59.3% (개발셋 정답 +59.8%와 0.5%p 차이 → 오답).
- 고친 방향: 표시 · 저장 값만 반올림하고, 차이 · 증감률 · 배수 · 연평균은 원값으로 계산 (골든셋 정답도 같은 방식).

## 8. 다음에 볼 곳 (건수 순, 개발셋에서 같은 유형으로 확인)

1. **표 칸 고르기** (경로 ③ 5건 + 경로 ② 표 3건 + 다중 표 2건): 일상어 ↔ 칸 이름 연결, 여러 칸 합산, 분자의 세부 조건. `dynamic_indicator.choose` · `uncovered` · `cell_pick`
2. **두 표를 합치는 질문** (다중 표 6건): 후보 검토가 "한 표에 다 있어야 함"으로 거절하지 않게, 분자 · 분모를 다른 표에서 가져오는 경로로 보내기. `search.check` · 사전에 없는 비율 나눠 계산
3. **비교 답의 배수** (비교 4건 전부): 답에 배수를 넣을지, 골든셋이 배수를 요구하지 않을지 결정
4. **답변 불가 유형 나누기** (5건): 후보 검토가 "맞는 표 없음"일 때 통계 질문 아님 · 없는 지역 단위 · 조건 만족 표 없음을 구분
5. **사전 지표의 기본 표와 질문 대상이 다를 때** (경로 ① 표 3건 + 다중 표 1건): 질문이 사전 지표보다 좁은 대상 · 방향을 물으면 표 찾기로 넘길지. `qa` 지표 매칭
6. **API 문항의 표 고르기** (④ 3건 + 다중 표 2건): 오래된 표(적재 안 됨)를 후보 검토가 "질문 주제 아님"으로 거절
7. **세부 구분이 있는 표로 넘기기 · 칸 후보 2개일 때 되묻기** (⑤ 2건 · ⑥ 3건)
